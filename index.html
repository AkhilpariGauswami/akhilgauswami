How I Think

02 / PROCESS
01 / Start with the Problem

Map the real friction, not the assumed one.

Every project starts with one question: what is the specific moment where the user's experience breaks down? Features are hypotheses. Problems are facts I can verify.

02 / Map Multiple Paths

Explore before committing.

I sketch at least three approaches before writing code. The first solution is usually the obvious one. The second is clever. The third is usually the right one.

03 / Ship & Learn

Build fast, learn faster.

I prefer shipping a working version to a perfect concept. Feedback from real use reveals what no amount of planning can anticipate. Iterate in public.
